HANA — Navegación responsive: hamburger sin JavaScript

Proyecto HANA · Restaurante japonés · Duración estimada: 90 min

1Contexto

Una de las piezas más universales de cualquier interfaz web es la navegación responsive. La solución habitual usa JavaScript, pero CSS puro tiene un truco elegante: el checkbox hack. Un <input type="checkbox"> actúa como botón de estado, y el CSS puede leer ese estado con el selector :checked.

El reto añadido: hacer que el menú sea de posición fija (siempre visible al hacer scroll) y que el input que lo controla sea visualmente invisible pero accesible para lectores de pantalla, usando solo CSS.

2Conceptos que se trabajan

position: fixed checkbox hack :checked selector visually-hidden ::before / ::after animados flex anidado margin-left: auto mobile-first @media min-width
⚠️
Nunca display: none para ocultar el input display: none elimina el elemento del árbol de accesibilidad. Los lectores de pantalla no podrían activar el menú. Se usa una técnica especial llamada visually hidden que lo oculta visualmente pero lo mantiene en el DOM.

3Resultado esperado

Tres estados del componente de navegación:

📱 Móvil — menú cerrado
📱 Móvil — menú abierto
🖥 Escritorio — ≥ 768px

ℹ️
El selector sibling ~ El selector .menu-toggle:checked ~ .nav-enlaces lee: "cuando el input con clase menu-toggle está marcado, aplica estilos a su hermano .nav-enlaces". Funciona porque ambos elementos son hijos directos de .nav.

5Guía paso a paso

  1. TODOs 2–4 — Header fijo: position: fixed; top: 0; left: 0; right: 0; z-index: 100. El header sale del flujo del documento y flota sobre el contenido.
  2. TODO 1 — Compensar el header: el header fijo tiene ~60px de altura. Añade padding-top: 60px al body para que el contenido principal no quede oculto bajo él.
  3. TODO 5 — Nav como flex container: display: flex; align-items: center; flex-wrap: wrap. El wrap es fundamental: permite que .nav-enlaces pase a la segunda línea cuando se abre en móvil.
  4. TODO 6 — Input visually hidden: position: absolute; width: 1px; height: 1px; overflow: hidden; clip: rect(0,0,0,0). El input desaparece visualmente pero los lectores de pantalla siguen pudiéndolo marcar. Nunca uses display: none ni visibility: hidden aquí.
  5. TODOs 7, 8 — Logo y hamburger en los extremos: .nav-logo con flex: none; .nav-hamburger con margin-left: auto. Este par de reglas crea el espacio vacío entre logo y botón.
  6. TODOs 9, 10 — Transiciones del icono: añade transition: transform .3s, background .3s a .hamburger-icon y sus pseudo-elementos para que la animación sea fluida.
  7. TODO 11 — Abrir el menú: .menu-toggle:checked ~ .nav-enlaces { display: flex; }. Cuando el checkbox está marcado, el menú se hace visible.
  8. TODOs 12–14 — Icono en X: la línea central se hace transparente (background: transparent); las líneas ::before y ::after se trasladan al centro (top: 0) y se rotan ±45°.
  9. TODO 15 — Cerrado por defecto: .nav-enlaces { display: none }. En móvil el menú empieza oculto.
  10. TODOs 16, 17 — Layout escritorio: dentro de @media (min-width: 768px), quita el wrap (flex-wrap: nowrap) y muestra .nav-enlaces en fila horizontal con display: flex; width: auto; flex-direction: row; border-top: none.

💡
¿Por qué flex-wrap: wrap + width: 100%? En Flexbox, un elemento con width: 100% ocupa toda la línea, pero solo si el container tiene flex-wrap: wrap. De lo contrario se encoge para caber en la misma fila. Esta combinación es la clave del menú desplegable que ocupa toda la anchura del header.
💡
El selector ~ requiere que los elementos sean hermanos .menu-toggle:checked ~ .nav-enlaces funciona porque ambos son hijos directos de .nav. Si el input estuviera dentro de otro elemento, el selector no llegaría a .nav-enlaces. Esta es la razón por la que el HTML tiene esa estructura específica.
